# Extension platform (design)

> Status: **design proposal, phase D.** Documentation only, no code. This file defines the "everything is a file" layout of `~/.forja` and `<project>/.forja`, the format of each kind of content, precedence and hot reload, and the format of Lua extensions: manifest, capabilities, approval by hash, sandbox, API and limits. MCP has its own file: `design/mcp.md`.

Read first: `AGENTS.md` (authorship; identifiers in English), `design/product.md` (sections 1, 4.4 and 5), `design/settings.toml` (groups `extensions` and `integrations`), `design/keymap.md` (scopes and precedence), `design/helper-profile.md` (helper profile) and `design/contracts.md` (registry of commands, settings and events).

## 0. Summary

- **Everything is a file.** Commands, helper profiles, skills, themes, keymaps, recipes and templates are text that you edit without recompiling. None of these formats contains executable code.
- **Two levels of extension.** Content (no code) and Lua extensions (code in a sandbox, with capabilities requested in the manifest and approved by hash). Rust modules belong to the repository and are not user extensions.
- **Nothing runs without approval.** An extension uses only the capabilities it asked for and you approved, in the exact approved content. Any change to its files requires a new approval.
- **Project content is not trusted by default.** A `.forja/` folder from a cloned repository gains the power to execute only after you trust the folder.

## 1. Layers and roots

| Layer | Root | Who writes | Trust |
|---|---|---|---|
| built-in | `content/` in the repository | us, reviewed in the PR | full (it is product code) |
| user | `~/.forja/` | you | full, but extension capabilities still need approval |
| project | `<project>/.forja/` (versionable) | whoever can change the repository | conditional: only after you trust the folder (section 4.2) |

`forja.toml` at the repository root is the per-repo configuration (setup, teardown, initial tabs, request commands; `repo_config` in the product). It is not part of `.forja/`, and this document does not cover it.

Every layer uses the same format: `content/commands/x.md`, `~/.forja/commands/x.md` and `<project>/.forja/commands/x.md` are identical files. Only the layer differs.

## 2. Layout

```
~/.forja/                          (user)             <project>/.forja/     (project)
├── keymap.toml                     your keymap overrides (highest precedence)
├── commands/*.md                   Anvil commands and /command in the chat
├── helpers/*.toml                  helper profiles (design/helper-profile.md)
├── skills/<name>/SKILL.md          skills (+ support files in the same folder)
├── themes/*.toml                   interface and terminal themes
├── keymaps/*.toml                  keymap packs (actions of Forja and commands)
├── recipes/*.toml                  terminal commands with a name
├── templates/*.md                  text templates (PR, note, handoff, routine)
└── extensions/<id>/                Lua extensions
    ├── extension.toml              manifest and requested capabilities
    ├── init.lua                    entry point
    ├── lib/*.lua                   the extension's own modules (optional)
    └── i18n/<locale>.toml          the extension's texts (optional)
```

Data that Forja writes (not configuration): `%APPDATA%\Forja\`, or `FORJA_DATA_DIR`. It holds the approval registry, project trust, each extension's storage and the logs. **Never inside the repository.**

Example extensions in the repository live in `extensions/<id>/` (generated by `cargo xtask new-extension`, as AGENTS.md says). To use one, copy its folder to `~/.forja/extensions/`.

### Naming

- Every identifier is in English: API functions and fields, ids, configuration keys, TOML and frontmatter keys, content folder names (`commands/`, `helpers/`, `skills/`, `themes/`, `keymaps/`, `recipes/`, `templates/`, `extensions/`) and enum values (`ask`, `accept-edits`, `automatic`, `full`).
- Portuguese appears only in user-facing text and in documents. Localized strings keep the `{ ["pt-BR"] = "...", en = "..." }` form.
- Scope names follow the product ids: `global`, `terminal`, `editor`, `browser`, `anvil` (the Anvil is the Bigorna).

## 3. Content formats

### 3.1 `commands/*.md`: command for the Anvil and the chat

A `.md` file with frontmatter in **TOML**, delimited by `+++`. We use TOML (not YAML) because the rest of Forja is TOML and we do not need a second parser. The body is the prompt text, with `{{placeholders}}`.

```markdown
+++
title = { pt-BR = "Revisar a bancada", en = "Review the bench" }
description = "Pede ao ajudante uma revisão do diff, com foco no que você escolher."
scope = ["anvil", "chat"]
run = "helper"
helper = "claude-code"
permissions = "ask"
context = ["request", "diff"]
shortcut = "Ctrl+Alt+R"
arguments = [ { name = "focus", required = false, default = "all" } ]
+++
Revise o diff desta bancada com foco em {{focus}}.
Aponte bugs, casos sem teste e nomes confusos. Não edite arquivos.

Pedido: {{request.title}}
```

| Key | Required | Type | Rule |
|---|---|---|---|
| `title` | yes | text or table per locale | what appears in the Anvil; the table has `pt-BR` and `en` |
| `description` | no | text or table | a support line in the Anvil |
| `scope` | no | list of `anvil`, `chat` | default: both |
| `run` | no | `helper` \| `recipe` \| `terminal` | default `helper`. `terminal` sends the text to the bench terminal and requires project trust |
| `helper` | no | profile id | default: `helper.default.profile` |
| `permissions` | no | `ask` \| `accept-edits` \| `automatic` \| `full` | the helper mode for this run. `automatic` and `full` require project trust |
| `recipe` | only with `run = "recipe"` | recipe id | see 3.6 |
| `shortcut` | no | key chord | **suggestion**: the shortcut you set in `keymaps/` always wins |
| `context` | no | list | `request`, `diff`, `bench`, `files:<glob>` (read only inside the project scope) |
| `arguments` | no | list of tables | `name`, `required`, `default`; they become `{{name}}` in the body |

Rules:
- An unknown key produces a warning in the diagnostics, not an error, so the format can grow.
- The body cannot be empty when `run` is `helper` or `terminal`.
- The id of a command is `cmd.<file-name-without-.md>`. A command cannot use the id of a built-in command (`bench.*`, `anvil.*` and the others).
- `{{context}}` in the body receives the content of the sources listed in `context`. Unknown placeholders stay as written and produce a warning.

### 3.2 `helpers/*.toml`: helper profiles

Format and fields in `design/helper-profile.md`. This file only decides precedence (section 4.1) and risk items (section 4.3): a project profile with `permissions.full` or `permissions.automatic` requires trust in the folder.

### 3.3 `skills/<name>/SKILL.md`: skills

A folder with a `SKILL.md` in the open format that the product cites (`design/product.md`, section 2). The frontmatter has `name` and `description`. The folder may have support files (examples, scripts, references). **The exact validation of the frontmatter is part of phase D, against the published specification of the format,** which was not read for this proposal.

How Forja offers a skill to a helper:
- in the context of the initial prompt, when `helper.launch.include_rules` is on;
- through an MCP tool (`skill.list` and `skill.get`, see `design/mcp.md`).

Forja **does not copy a skill into the repository** without recorded consent: copying into the bench is a write outside Forja's own folder.

### 3.4 `themes/*.toml`: themes

```toml
# themes/brasa-noturno.toml
name = "Brasa noturna"
base = "dark"                        # dark | light

[colors]                             # tokens from design/ui.md (final list when the ui-kit is delivered)
background = "#1B1714"
surface = "#252019"
text = "#F3E9DC"
accent = "#E8743B"

[terminal]
background = "#161311"
foreground = "#E6DCCD"
cursor = "#E8743B"
selection = "#3A2E26"
ansi = ["#161311", "#C75B4A", "#8DB05C", "#D9A441", "#5C8DB0", "#A477B0", "#5FA8A0", "#CFC5B4",
        "#5B5148", "#E07A66", "#A6CC75", "#EDBF5E", "#7DA9CC", "#BD8FCB", "#7CC4BB", "#F3E9DC"]
```

Contrast rule: text over background at **at least 4.5:1** (AA, `design/ui.md`). A theme that fails is refused with a diagnostic, and Forja keeps the previous theme. The 16 `ansi` values are required.

### 3.5 `keymaps/*.toml` and `~/.forja/keymap.toml`: keymaps

Two places, both needed:
- **Packs** in `keymaps/*.toml` (user and project): a set of bindings that you can enable, share or version.
- **Overrides** in `~/.forja/keymap.toml` (user only): your personal changes to any binding.

Same schema in both:

```toml
# keymaps/mine.toml
[[binding]]
id = "cmd.review-bench"              # built-in action or command id (3.1 and section 5)
key = "Ctrl+Alt+R"
scope = "global"
title = { pt-BR = "Revisar a bancada", en = "Review the bench" }

[[binding]]
id = "find.file"                     # built-in action: replaces the default key
key = "Ctrl+Shift+P"
scope = "global"
title = { pt-BR = "Achar arquivo", en = "Find file" }

[[binding]]
id = "tab.reopen"
disable = true                       # removes the default key without adding another
```

Rules:
- Precedence, lowest to highest: built-in (`design/keymap.toml`), packs of the user, packs of the project, `~/.forja/keymap.toml`. For the same `id` the higher level wins.
- **A project pack cannot bind Forja's own actions** (`anvil.*`, `terminal.*`, `bench.*` and the other built-in actions). It can bind only its own commands (`cmd.*`, `ext.*`). This prevents a repository from taking over Ctrl+K.
- A conflict inside the same scope is refused (`keymap.conflict_policy` decides between warning and blocking the save, and the kernel contract test always blocks). The rest follows `design/keymap.md`.
- The `title` field is localized here. `design/keymap.toml` still uses `title_pt` and `title_en` (decision 10 in section 7).

### 3.6 `recipes/*.toml`: recipes

```toml
# recipes/project.toml
[[recipe]]
id = "lint"
title = { pt-BR = "Lint do workspace", en = "Workspace lint" }
command = "cargo clippy --workspace --all-targets -- -D warnings"
scope = "project"                    # global | project
enter = false                        # true: runs without stopping first (recipe.execute.confirm)
directory = "."                      # relative to the bench
```

A recipe runs a shell command (`recipe.shell.default`). For that reason **a project recipe runs only after you trust the folder** (section 4.2). Before that, it appears listed and disabled, with the reason.

### 3.7 `templates/*.md`: text templates

> **Decision taken in this proposal, to confirm with the product:** "templates" are **text templates** (PR description, note and handoff of the muster, routine report), not AI models. An AI model is a choice of helper (`models` in the profile) and of settings.

```markdown
+++
name = "PR description"
use = "pr"                           # pr | note | handoff | routine
+++
## What changes
{{summary}}

## How to test
{{tests}}
```

Placeholders use the form `{{name}}`. Forja fills the ones it knows (`request.title`, `bench.branch`, `diff.summary`) and asks for the others.

## 4. Precedence, trust and reload

### 4.1 How an item of each type overrides another

| Type | Key | Conflict rule |
|---|---|---|
| commands | `cmd.<name>` | the higher level replaces; cannot use a built-in id |
| helpers | profile `id` | the higher level replaces; a project profile with risk requires trust (4.3) |
| skills | folder name | the whole folder replaces |
| themes | file `name` | the higher level replaces; contrast validated |
| keymaps | action `id` | merged by `id`; the higher level wins; a project cannot bind Forja's actions (3.5) |
| recipes | `id` | the higher level replaces; running depends on trust (4.2) |
| templates | `name` | the higher level replaces |
| extensions | `id` | **no replacement:** an `id` repeated between user and project disables both and warns |

Read order: built-in, user, project. When a tie is not resolved by this table, the file read last in alphabetical order wins, and the diagnostic shows the conflict. The order never depends on the file system's order.

### 4.2 Trust of a project folder

The first time a project with `.forja/` is opened, Forja shows what the folder contains and asks. The confirmation applies to the approved **content** (a hash of the folder). If the risk items change, the confirmation is asked again.

Without trust, the project loads only content that has no effect:
- commands with `run = "helper"` and `permissions = "ask"` (or `accept-edits`);
- skills, themes, templates;
- keymap bindings that do not reach a risky action;
- helper profiles with `ask` or `accept-edits`.

Project extensions **never** load because the folder is trusted: they also need approval by hash (section 5.4).

Trust registry: `FORJA_DATA_DIR\trust\projects.json`, with the canonical path, the folder hash and the date. Never inside the repository.

### 4.3 Risk items

| Item | Why it is risky | Without trust |
|---|---|---|
| any recipe | runs shell | listed, disabled |
| command with `run = "terminal"` | sends text to the terminal | disabled |
| command or profile with `permissions = "automatic"` or `"full"` | the helper acts without asking | disabled, with the reason |
| keymap binding that reaches a recipe or terminal | the shortcut starts an execution | disabled |
| Lua extension | code | never loads without approval by hash |

### 4.4 Hot reload

- **File watching** per root (`notify`), with a debounce of 300 ms. A partial write is read only after 300 ms with no further change to the file.
- **Reload per file**, not per folder: a change reloads only the file it touches.
- **Atomic swap:** the file is read and validated before it replaces the previous version. If reading fails, **the previous version keeps working** and the diagnostic shows the error with line and column.
- **Removal** of a file removes its items from the registry.
- **UI update:** the Anvil, the Board and Settings are redrawn with the new items. No screen blocks.
- **Extensions:** watching `extensions/` reloads only if `extension.dev.watch` is on (default off). With watching off, a change is detected by its hash and the extension moves to the `changed` state (5.4), where it does not run.

### 4.5 Diagnostics

Errors and warnings of content appear in one list (Settings > Diagnostics), with file, line and message. A content error never brings down the app or other items.

## 5. Lua extensions

### 5.1 Layout and lifecycle

An extension is a folder: `extension.toml`, `init.lua`, optionally `lib/*.lua` and `i18n/*.toml`. There are no other entry points.

Lifecycle: **discover** (read the manifest) → **compute the hash** → **check the state** (5.4) → **create a new Lua state** → **run `init.lua`** (static registration: commands, the settings schema and event subscriptions can be declared only here) → **receive events and runs** → **unload** when disabled, uninstalled or when the app closes.

Each extension has its own Lua state and its own worker thread. The interface never runs Lua or I/O (AGENTS.md, section 4): it only sends messages and receives panel trees.

### 5.2 `extension.toml`

```toml
id = "todo-counter"
name = { pt-BR = "Contador de TODOs", en = "TODO counter" }
version = "1.0.0"
author = "Forja"
description = { pt-BR = "Conta TODO e FIXME nos arquivos do projeto.", en = "Counts TODO and FIXME in project files." }
api = "1"
entry = "init.lua"

[capabilities]
commands = true
"ui.panel" = true
settings = true
events = ["project.opened"]
"fs.read" = ["**/*.rs", "**/*.ts", "**/*.md"]
```

| Key | Required | Rule |
|---|---|---|
| `id` | yes | `[a-z][a-z0-9-]{1,39}`; unique. It prefixes commands (`ext.<id>.<command>`) and configuration keys |
| `name` | yes | text or table per locale |
| `version` | yes | semantic version (`MAJOR.MINOR.PATCH`) |
| `author` | yes | informative |
| `description` | no | text or table per locale |
| `api` | yes | API version the extension requires. Today `"1"`. An extension with a higher `api` than Forja's does not load |
| `entry` | no | default `init.lua` |
| `[capabilities]` | no | absent = no capability (5.3) |

### 5.3 Capabilities

The extension declares what it wants. The app shows the request in the approval, with its scope, and nothing beyond it is granted.

| Key | Form | Grants | Default |
|---|---|---|---|
| `commands` | boolean | `forja.commands.register` | false |
| `"ui.panel"` | boolean | `forja.ui.panel` and `forja.ui.remove_panel` | false |
| `settings` | boolean | `forja.settings.schema`, `get`, `set` (only its own keys) | false |
| `events` | list of event names | `forja.on` only for the listed events (5.7.3) | empty |
| `"terminal.send"` | boolean | `forja.terminal.list` and `forja.terminal.send` | false |
| `"git.read"` | boolean | `forja.git.*` (read only) | false |
| `"fs.read"` | list of globs relative to the project | `forja.fs.list`, `read`, `exists` inside the globs | empty |
| `"fs.write"` | list of globs relative to the project | `forja.fs.write` inside the globs | empty |
| `http` | list of hosts | `forja.http` for those hosts | empty |
| `"ui.open_url"` | list of hosts | `forja.ui.open_url` for those hosts | empty |

Without the declared capability, the function exists but fails with `[capability_denied]`.

**Always available, no capability:** `forja.log`, `forja.notify`, `forja.i18n`, `forja.store`, `forja.time`, `forja.project.path`, `forja.bench.current`, `forja.load`. Each has its own limit (5.8).

**Configuration gates** (`design/settings.toml`, group `extensions`):
- `extension.network.allow` (off): must be on for `http` and for `ui.open_url` with a host other than `localhost`. Opening `localhost` generates no traffic from Forja and is not gated.
- `extension.fs.allow_outside_project` (off): globs with `..` or an absolute path are refused without it.
- `extension.process.allow_spawn` (off): reserved. API v1 has no process function.

The `fs` globs apply to the active bench (each bench is a worktree of the project). Patterns **always denied**, even with a broad `fs.read`: `.git/**`, `**/.env`, `**/.env.*`, `**/*.pem`, `**/*.key`. Writing also denies `.forja/**`.

### 5.4 Approval by hash

- **Hash:** SHA-256 over the content of every file in the folder, in order of relative path, each entry prefixed by its size. Any byte change changes the hash.
- **Registry:** `FORJA_DATA_DIR\approvals\extensions.json`, with `id`, `version`, hash, approved capabilities (with scopes) and date. Never inside the repository.
- **Approving** binds the current hash to the capabilities shown. The approval screen lists each capability with its scope, the files and the hash. On an update, it shows what changed in the capabilities.
- **States:**

| State | Meaning | Runs? |
|---|---|---|
| `pending` | never approved | no |
| `active` | hash equal to the approved one | yes |
| `changed` | hash different from the approved one | no; shows what changed and asks for approval |
| `invalid` | manifest or Lua with a syntax error | no; shows the error with its line |
| `suspended` | repeated errors (5.8) or a state failure | no, until re-enabled |
| `conflict` | same `id` in user and project | no |

- **Development mode** (`extension.dev.watch` on, only for extensions in `~/.forja/extensions/`): when the manifest has exactly the same approved capabilities, the new code version is approved again automatically. The re-approval is logged. **Decision to confirm:** this trades "any change asks for approval" for "a code change inside capabilities already approved". There is no privilege escalation, because the capabilities are the same, but the code changes without asking. Project extensions never enter this mode.

### 5.5 Sandbox

1. **One Lua state per extension.** No state is shared between extensions, and no global of one extension exists in another.
2. **Libraries loaded by explicit list:** `table`, `string`, `math`, `utf8`, `coroutine`. The default loading of `Lua::new` is not used.
3. **Not loaded:** `io`, `os`, `package` (`require`, `package.loadlib`, `package.cpath`), `debug`, `ffi` and `jit`.
4. **Base functions removed or replaced:**
   - `dofile` and `loadfile` removed;
   - `load` kept only in text mode (`mode = "t"`), with the extension's own environment. The Lua 5.4 manual lists `load`, `loadfile` and `dofile` as base functions and defines `"t"` as the mode that accepts only text (**to confirm: reading of §6.1 of the manual, which did not load in this proposal**);
   - `string.dump` removed (it produces binary bytecode);
   - `print` replaced by `forja.log.info`.
5. **No native modules and no `require`.** Code from another file enters only through `forja.load(path)`, with a path relative to the extension folder, a `.lua` extension, up to 256 KB per file and 16 files.
6. **No direct access to the operating system.** There is no process function in v1. Files, network and terminal go only through the `forja.*` functions of the approved capabilities.
7. **Network only through the API.** `forja.http` with an allowed host, `https` only. `forja.ui.open_url` opens the system browser **only as the result of a user action** (a click on a button or running a command from the Anvil). A call from a background event is refused.
8. **No secrets.** The extension cannot read the system vault, receives no tokens, and cannot send `Authorization` or `Cookie` headers with `forja.http`.
9. **Execution off the interface.** Every call runs on the extension's thread. A call that blocks does not freeze the window.
10. **Data isolation.** The extension reads only its own configuration keys, its own store and its own logs.

### 5.6 Threading and order

- Events of one extension are delivered **in arrival order**, through a queue per extension. Events of different extensions may run in parallel.
- A command run enters the same queue as the events.
- The interface receives the panel tree already built; it never calls Lua.

### 5.7 API

Conventions: function and field names are English, as in the panel nodes. Ids (events, capabilities, keys) are lowercase English with dots. Where text is accepted, a string or a locale table `{ ["pt-BR"] = "...", en = "..." }` is accepted, resolved by the current locale (fallback to `en`, then to the first available locale).

#### 5.7.1 Context and utilities

```lua
forja.api                      -- "1"
forja.extension.id             -- "todo-counter"
forja.extension.version        -- "1.0.0"

forja.log.debug(text)          -- forja.log.info / warn / error
forja.load(path)               -- runs a .lua file of the extension and returns what it returns (cached by path)
```

`forja.log` writes to `FORJA_DATA_DIR\logs\extensions\<id>.log` (1 MB, three files). The minimum level is `extension.log.level`.

#### 5.7.2 `forja.commands.register`

Only during `init.lua`. Capability: `commands`.

```lua
forja.commands.register({
  id = "count",                                          -- local; becomes ext.<id>.count
  title = { ["pt-BR"] = "Contar TODOs", en = "Count TODOs" },
  description = "opcional",
  shortcut = "Ctrl+Alt+T",                               -- suggestion; the user's shortcut wins
  arguments = { { name = "folder", type = "text", required = false, default = "." } },
  available = function(ctx) return true end,             -- optional; false hides the command
  run = function(args, ctx)
    -- args: table with the requested arguments
    -- ctx: { bench = { id, name, branch, path }, locale = "pt-BR" }
    return { message = "pronto" }                        -- optional: shows as a notice
  end,
})
```

A command is not exposed to MCP by default (`design/mcp.md`). Up to 50 commands per extension.

#### 5.7.3 `forja.on` and events

Only during `init.lua`, and only for events listed in `events` of the manifest.

```lua
local subscription = forja.on("helper.finished", function(ev)
  forja.log.info("helper " .. ev.id .. " finished: " .. ev.result)
end)
subscription:cancel()   -- optional
```

| Event | Payload (`ev`) | When |
|---|---|---|
| `app.ready` | `{}` | the app finished opening |
| `app.closing` | `{}` | the app is about to close (short time: do no heavy work) |
| `project.opened` | `{ path, name }` | a project was opened |
| `bench.created` | `{ id, name, branch }` | a bench was created |
| `bench.selected` | `{ id }` | the active bench changed |
| `bench.archived` | `{ id }` | a bench was archived |
| `helper.started` | `{ id, bench, profile }` | a helper was started |
| `helper.status` | `{ id, bench, state }` | `state` is `working`, `needs_you`, `done` or `error` |
| `helper.finished` | `{ id, bench, result }` | `result` is `done`, `failed` or `blocked` (muster handoff) |
| `routine.finished` | `{ id, name, summary, duration_s }` | a routine finished successfully |
| `routine.failed` | `{ id, name, error }` | a routine failed |
| `git.changed` | `{ bench, branch }` | git refs or status changed (grouped every 500 ms) |
| `file.saved` | `{ path }` | a project file was saved (relative path) |
| `port.detected` | `{ port, bench, process }` | a port started having a process listening |
| `port.closed` | `{ port }` | the port is no longer in use |
| `settings.changed` | `{ key }` | a key of the extension itself changed |

An event not declared in `events` raises `[capability_denied]` at subscription. Up to 64 subscriptions per extension.

#### 5.7.4 `forja.ui.panel` and the declarative tree

Capability: `ui.panel`. Slots: `right_panel` (right panel), `bench_tab` (bench tab), `sidebar`.

```lua
forja.ui.panel({
  id = "todos",                                          -- unique within the extension
  title = { ["pt-BR"] = "TODOs", en = "TODOs" },
  slot = "right_panel",
  tree = {                                               -- list of nodes
    forja.ui.text({ value = "3 ocorrências", style = "title" }),
    forja.ui.button({ id = "refresh", label = "Atualizar", action = function(ev) end }),
  },
})
forja.ui.remove_panel("todos")
```

**Nodes.** The node names are the ones asked for in the design brief. `group` is a container that was not in the original list; it was added because the children of `form` and of a panel need grouping.

| Node | Fields | Action |
|---|---|---|
| `text` | `id?`, `value`, `style?` (`normal`, `title`, `secondary`, `warning`, `error`, `code`) | — |
| `button` | `id`, `label`, `primary?`, `disabled?`, `action` | `ev.kind = "click"` |
| `list` | `id`, `items` (`{ id, label, detail? }`), `action` | `ev.item` = id of the chosen item |
| `table` | `id`, `columns` (`{ key, label, width? }`), `rows` (`{ id, <key> = value }`), `action?` | `ev.row` = id of the row |
| `form` | `id`, `fields` (list of `field`), `submit` (`{ label, action }`) | `ev.values` = `{ [id] = value }` |
| `field` | `id`, `type` (`text`, `number`, `choice`, `boolean`, `path`), `label`, `value?`, `options?` (`{ { value, label } }`), `required?`, `range?` (`{ min, max }`), `action?` | `ev.value` on `change` |
| `divider` | — | — |
| `group` | `id?`, `title?`, `children` | — |

Constructors: `forja.ui.text{...}`, `forja.ui.button{...}`, and so on.

**Update model.** State lives in Lua. The tree is **data**: the interface executes no code when it draws.
- Calling `forja.ui.panel` again with the same `id` **replaces the whole tree**. The interface compares it with the previous tree by each node's `id` and updates only what changed. Focus, scroll and selection are kept while the `id` exists.
- Nodes without `id` are identified by position and type. So **every interactive node needs an `id`**.
- Each `action` receives `ev` with `node` (node id), `kind` (`click`, `change`, `select`, `submit`) and the node's fields. An action that changes the panel calls `forja.ui.panel` again.
- Renders are **coalesced**: at most one every 100 ms per panel. More than 10 per second is an error, and the intermediate renders are discarded.
- A panel created outside `init` (inside an event or a command) is allowed. Registering commands and events is not.
- Limits: 500 nodes per panel, depth 4, 1000 rows per table, 1000 items per list (5.8).

**Invalid tree** (unknown type, repeated `id`, missing required field) is refused, and the error shows the path of the node: `panel "todos" > table#table > columns[2].key`. The previous panel stays on screen.

#### 5.7.5 `forja.ui.open_url`

#### 5.7.7 `forja.terminal`

Capability: `"terminal.send"`.

```lua
local terminals = forja.terminal.list()                -- { { id, title, kind = "shell" | "helper" } }
forja.terminal.send("current", "npm test", { enter = true })
```

- `id` accepts `"current"` (the active terminal of the bench) or an id from `list()`.
- The text has up to 4096 bytes and no control characters except tab. `enter = true` adds the Enter key.

- Up to 10 sends per minute.

#### 5.7.8 `forja.git` (read)

Capability: `"git.read"`. Run by the host, inside the bench.

```lua
forja.git.status()                    -- { { path, state } }; state: modified, new, deleted, conflict, untracked
forja.git.branch()                    -- "main"; "HEAD" in detached mode
forja.git.remote_url("origin")        -- string or nil
forja.git.log({ limit = 50, since = "2026-11-12", ["until"] = nil })   -- { { hash, author, date, subject } }
forja.git.diff_stat()                 -- { files, insertions, deletions }
```

There is no git write in v1 (no commit, checkout or push).

#### 5.7.9 `forja.fs`

Paths are relative to the project root. An absolute path and `..` are refused, unless `extension.fs.allow_outside_project` is on and approved.

```lua
forja.fs.list("**/*.rs")              -- paths matching the glob, without what .gitignore excludes; up to 5000
forja.fs.exists("Cargo.toml")         -- boolean
forja.fs.read("src/main.rs")          -- UTF-8 text up to 1 MB; binary raises an error
forja.fs.write("notes.md", text)      -- capability fs.write; up to 1 MB; atomic write
```

#### 5.7.10 `forja.http`

Capability: `http` with the list of hosts. Only `https`, exact host, no cookies, and no proxy configured by the extension.

```lua
local r = forja.http.get("https://api.github.com/repos/owner/repo", {
  headers = { Accept = "application/vnd.github+json" },
  timeout_ms = 5000,                  -- default 5000; maximum 10000
})
-- r = { status = 200, headers = {...}, body = "..." }
forja.http.post(url, body, opts)      -- same shape
```

Response up to 2 MB. Redirects only to a host on the list. Up to 30 requests per minute. A network error, a timeout or a host not allowed raises a Lua error with a code.

#### 5.7.11 `forja.notify`

No capability. Up to 10 per minute per extension; three visible at the same time.

```lua
forja.notify({ title = "Routine failed", text = "build: exit 101", level = "error" })   -- info | warning | error
```

#### 5.7.12 `forja.i18n`

No capability. Texts in the extension's own `i18n/<locale>.toml`, with fallback to `en`, then to the key itself.

```lua
forja.i18n.t("routine_failed")         -- "Rotina falhou" in pt-BR
forja.i18n.t("total", { n = 3 })       -- interpolates {n} in the text
forja.i18n.locale()                    -- "pt-BR" | "en"
```

#### 5.7.13 `forja.store`

No capability. The extension's private storage, in `FORJA_DATA_DIR\extensions\<id>\store.json`, outside the repository.

```lua
forja.store.set("last:build", { summary = "ok", at = forja.time.now() })
forja.store.get("last:build")          -- table or nil
forja.store.remove("last:build")
```

Key up to 128 characters. Value: string, number, boolean, or a table with string keys and JSON values. Total up to 1 MB. Uninstalling the extension does **not** delete its storage; a separate "delete data" action does.

### 5.8 Errors and limits

#### Errors

Every failure becomes a Lua error with a code in brackets at the start of the message, for example `[capability_denied] fs.read: "config/prod.toml" outside **/*.rs`. The author can handle it with `pcall`, and the interface shows the code.

| Code | When |
|---|---|
| `capability_denied` | function without the capability, or outside its scope |
| `limit` | a limit from the table below was reached |
| `time` | the CPU budget or the I/O wait budget was exceeded |
| `memory` | the Lua state went past its memory limit |
| `argument` | value outside the format (type, range, file that is not UTF-8) |
| `tree` | invalid panel tree (5.7.4) |
| `host` | an I/O call of the host failed (git, network, file) |
| `internal` | a failure in the extension runtime itself |

**Response levels:**

1. **Error in an action** (button, command, event): the call is aborted, the error goes to the extension's log, and the interface shows a short notice with "see log".
2. **Repeated errors:** three errors in 60 s put the extension in **`suspended`** until you re-enable it. Its panels disappear.
3. **Memory exceeded:** the Lua state is discarded and recreated, `init.lua` runs again, and the panels are cleared. A notice explains why.
4. **Failure inside the runtime itself:** caught at the extension's boundary; the extension goes to `suspended`. The app keeps working.

**Time budget.** The **CPU** time of a Lua call is capped at `extension.lua.timeout_ms` (default 1000 ms). The clock **pauses** while the host does I/O (git, network, file), and there is a separate cap of **30 s of waiting per call**. A call that exceeds the CPU cap is interrupted with `[time]`.

> **Requirement to validate in the implementation:** interruption by instruction count. The mlua documentation read here is the current one (`latest`, 0.12.2), and the workspace now pins **mlua 0.12** (commit `90ae754` on main). It shows `set_memory_limit` and an instruction hook, but the availability of the hook on `lua54` was not confirmed. If the hook is not available, the alternative is Lua 5.4's own hook API (`lua_sethook`) installed by the host through FFI, which does not depend on the `debug` library that the extension does not have.

#### Limits

| Limit | Default | Adjustable | When exceeded |
|---|---|---|---|
| memory per Lua extension | `extension.lua.memory_mb` = 64 | yes (8–512) | `[memory]`, state restarted |
| CPU per call | `extension.lua.timeout_ms` = 1000 | yes (100–10000) | `[time]` |
| I/O wait per call | 30 s | no | `[time]` |
| text read or written | 1 MB | no | `[argument]` |
| HTTP response | 2 MB | no | `[host]` |
| entries of `fs.list` | 5000 | no | truncates and warns |
| table rows and list items | 1000 | no | truncates and warns |
| nodes per panel / depth | 500 / 4 | no | `[tree]` |
| renders per panel | 10 per second | no | discards intermediate renders |
| notifications | 10 per minute | no | discards |
| HTTP requests | 30 per minute | no | `[limit]` |
| sends to the terminal | 10 per minute, 4 KB each | no | `[limit]` |
| commands per extension | 50 | no | refuses the registration |
| event subscriptions | 64 | no | refuses the subscription |
| storage per extension | 1 MB | no | `[limit]` |
| Lua file | 256 KB, 16 files | no | does not load |
| repeated errors | 3 in 60 s | no | `suspended` |

### 6.1 `todo-counter`: count of TODO and FIXME

`extension.toml`:

```toml
id = "todo-counter"
name = { pt-BR = "Contador de TODOs", en = "TODO counter" }
version = "1.0.0"
author = "Forja"
description = { pt-BR = "Conta TODO e FIXME nos arquivos do projeto.", en = "Counts TODO and FIXME in project files." }
api = "1"

[capabilities]
commands = true
"ui.panel" = true
settings = true
events = ["project.opened"]
"fs.read" = ["**/*.rs", "**/*.ts", "**/*.md"]
```

`init.lua`:

```lua
forja.settings.schema({
  {
    name = "max_files",
    type = "number",
    default = 300,
    range = { min = 10, max = 2000 },
    label = { ["pt-BR"] = "Arquivos analisados", en = "Files scanned" },
    help = { ["pt-BR"] = "Limite de arquivos lidos por contagem.", en = "File limit per scan." },
  },
})

local MARKERS = { "TODO", "FIXME" }
local PATTERNS = { "**/*.rs", "**/*.ts", "**/*.md" }

local function count()
  local maximum = forja.settings.get("max_files")
  local rows, read = {}, 0
  for _, pattern in ipairs(PATTERNS) do
    for _, path in ipairs(forja.fs.list(pattern)) do
      if read >= maximum then break end
      read = read + 1
      local ok, text = pcall(forja.fs.read, path)   -- a large or binary file does not stop the count
      if ok then
        local total = 0
        for _, marker in ipairs(MARKERS) do
          local _, n = text:gsub(marker, "")
          total = total + n
        end
        if total > 0 then
          rows[#rows + 1] = { id = path, file = path, total = total }
        end
      end
    end
  end
  table.sort(rows, function(a, b) return a.total > b.total end)
  return rows
end

local function refresh()
  local rows = count()
  local sum = 0
  for _, r in ipairs(rows) do sum = sum + r.total end
  forja.ui.panel({
    id = "todos",
    title = { ["pt-BR"] = "TODOs", en = "TODOs" },
    slot = "right_panel",
    tree = {
      forja.ui.text({ value = ("%d ocorrências em %d arquivos"):format(sum, #rows), style = "title" }),
      forja.ui.button({
        id = "refresh",
        label = { ["pt-BR"] = "Atualizar", en = "Refresh" },
        action = function(ev) refresh() end,
      }),
      forja.ui.table({
        id = "table",
        columns = {
          { key = "file", label = { ["pt-BR"] = "Arquivo", en = "File" } },
          { key = "total", label = "TODOs", width = 80 },
        },
        rows = rows,
      }),
    },
  })
end

forja.commands.register({
  id = "count",
  title = { ["pt-BR"] = "Contar TODOs no projeto", en = "Count TODOs in project" },
  run = function(args, ctx)
    refresh()
    return { message = "Contagem atualizada." }
  end,
})

forja.on("project.opened", function(ev)
  refresh()
end)
```

```lua
forja.settings.schema({
  {
    name = "author",
    type = "text",
    default = "",
    label = { ["pt-BR"] = "Autor (vazio = todos)", en = "Author (empty = everyone)" },
```

### 6.3 `open-pr`: PR page for the current branch

`extension.toml`:

```toml
id = "open-pr"
name = { pt-BR = "Abrir PR", en = "Open PR" }
version = "1.0.0"
author = "Forja"
api = "1"

[capabilities]
commands = true
settings = true
"git.read" = true
"ui.open_url" = ["github.com"]
```

`init.lua`:

```lua
forja.settings.schema({
  {
    name = "base",
    type = "text",
    default = "main",
    label = { ["pt-BR"] = "Branch base do PR", en = "PR base branch" },
  },
})

-- Accepts git@github.com:owner/repo.git and https://github.com/owner/repo(.git).
local function owner_and_repo(remote)
  local owner, repo = remote:match("github%.com[:/]([^/]+)/([^/]+)$")
  if not owner then return nil end
  return owner, (repo:gsub("%.git$", ""))
end

local function pr_link(branch, base)
  local remote = forja.git.remote_url("origin")
  if not remote then return nil, "a bancada não tem remoto origin" end
  local owner, repo = owner_and_repo(remote)
  if not owner then return nil, "o remoto origin não é do GitHub" end
  return ("https://github.com/%s/%s/compare/%s...%s?expand=1"):format(owner, repo, base, branch)
end

forja.commands.register({
  id = "open",
  title = { ["pt-BR"] = "Abrir PR da branch atual", en = "Open PR for current branch" },
  run = function(args, ctx)
    local branch = forja.git.branch()
    if branch == "" or branch == "HEAD" then
      forja.notify({ title = "Abrir PR", text = "A bancada não está numa branch.", level = "warning" })
      return nil
    end
    local url, err = pr_link(branch, forja.settings.get("base"))
    if not url then
      forja.notify({ title = "Abrir PR", text = err, level = "error" })
      return nil
    end
    -- Allowed because the user ran the command from the Anvil.
    forja.ui.open_url(url)
    return { message = "Página de PR aberta." }
  end,
})
```

`extension.toml`:

```toml
id = "ports-panel"
name = { pt-BR = "Painel de portas", en = "Ports panel" }
version = "1.0.0"
author = "Forja"
api = "1"

[capabilities]
```

`init.lua`:

```lua
forja.settings.schema({
  {
    name = "ignore",
    type = "text",
    default = "",
    label = { ["pt-BR"] = "Portas ignoradas", en = "Ignored ports" },
    help = { ["pt-BR"] = "Números separados por vírgula, como 5432,6379.", en = "Comma-separated numbers, like 5432,6379." },
  },
})

local open = {}   -- port (number) -> { process = text }

local function ignored()
  local set = {}
  for number in forja.settings.get("ignore"):gmatch("%d+") do
    set[tonumber(number)] = true
  end
  return set
end

local function render()
  local ignore = ignored()
  local items = {}
  for port, info in pairs(open) do
    if not ignore[port] then
      items[#items + 1] = {
        id = tostring(port),
        label = ("localhost:%d"):format(port),
        detail = info.process or "",
      }
    end
  end
  table.sort(items, function(a, b) return tonumber(a.id) < tonumber(b.id) end)
  forja.ui.panel({
    id = "ports",
    title = { ["pt-BR"] = "Portas", en = "Ports" },
    slot = "right_panel",
    tree = {
      forja.ui.list({
        id = "list",
        items = items,
        action = function(ev)
          forja.ui.open_url("http://localhost:" .. ev.item)   -- user click; localhost is not gated
        end,
      }),
      forja.ui.text({
        value = (#items == 0) and "Nenhuma porta aberta." or ("%d abertas"):format(#items),
        style = "secondary",
      }),
    },
  })
end

forja.on("port.detected", function(ev)
  open[ev.port] = { process = ev.process }
  render()
end)

forja.on("port.closed", function(ev)
  open[ev.port] = nil
  render()
end)

render()
```

### 6.5 `routine-reminder`: notice and last result of watched routines

`extension.toml`:

```toml
id = "routine-reminder"
```

`init.lua`:

```lua
forja.settings.schema({
  {
    name = "routines",
    type = "text",
    default = "",
    label = { ["pt-BR"] = "Rotinas vigiadas", en = "Watched routines" },
    help = { ["pt-BR"] = "Nomes separados por vírgula.", en = "Comma-separated names." },
  },
  {
    name = "notify_success",
    type = "toggle",
    default = false,
    label = { ["pt-BR"] = "Avisar quando dá certo", en = "Notify on success" },
  },
})

local function watched()
  local names = {}
  for name in forja.settings.get("routines"):gmatch("[^,]+") do
    names[#names + 1] = name:match("^%s*(.-)%s*$")
  end
  return names
end

local function is_watched(name)
  for _, v in ipairs(watched()) do
    if v == name then return true end
  end
  return false
end

forja.on("routine.finished", function(ev)
  if not is_watched(ev.name) then return end
  forja.store.set("last:" .. ev.name, { summary = ev.summary, at = forja.time.now(), ok = true })
  if forja.settings.get("notify_success") then
    forja.notify({ title = forja.i18n.t("routine_done"), text = ev.name .. ": " .. ev.summary, level = "info" })
  end
end)

forja.on("routine.failed", function(ev)
  if not is_watched(ev.name) then return end
  forja.store.set("last:" .. ev.name, { summary = ev.error, at = forja.time.now(), ok = false })
  forja.notify({ title = forja.i18n.t("routine_failed"), text = ev.name .. ": " .. ev.error, level = "error" })
end)

forja.commands.register({
  id = "latest",
  title = { ["pt-BR"] = "Ver últimas rotinas vigiadas", en = "Show watched routines" },
  run = function(args, ctx)
    local rows = {}
    for _, name in ipairs(watched()) do
      local last = forja.store.get("last:" .. name)
      rows[#rows + 1] = {
        id = name,
        routine = name,
        result = last and last.summary or forja.i18n.t("no_result"),
        when = last and last.at or "—",
      }
    end
    forja.ui.panel({
      id = "routines",
      title = { ["pt-BR"] = "Rotinas", en = "Routines" },
      slot = "right_panel",
      tree = {
        forja.ui.table({
          id = "table",
          columns = {
            { key = "routine", label = { ["pt-BR"] = "Rotina", en = "Routine" } },
            { key = "result", label = { ["pt-BR"] = "Último resultado", en = "Last result" } },
            { key = "when", label = { ["pt-BR"] = "Quando", en = "When" }, width = 180 },
          },
          rows = rows,
        }),
      },
    })
    return nil
  end,
})
```
